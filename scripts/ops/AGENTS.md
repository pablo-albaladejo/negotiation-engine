# scripts/ops/ — Start and watch the day

One command to start everything and another to check that it will work. Runbook: [`DAY2.md`](../../DAY2.md).

## Files

- **`doctor.mjs`** — `pnpm bazaar:doctor [--fast]`: read-only, one ✓/✗ line per check and exit 1 if any fails (3 if only .env.broker is missing: `pnpm bazaar:up` then starts without the shadow broker). `.env` with `BAZAAR_KEY` (never printed), .env.broker with the broker key (`BAZAAR_BROKER_KEY`; if missing, ✗ only for the shadow broker), Node ≥ 22 and pnpm, git on DAY2 (clean or dirty tree, ahead of or behind origin), `pnpm typecheck`, `pnpm test` and `pnpm docs:check` (`--fast` skips them), `/api/clock` and `/api/me` (tick, game time, gates, limits), viewer port (`--viewer-port`, 5199: free or already serving the viewer) and `pnpm bazaar:play --dry-run --once` (`--play-timeout`, 240 s). That last check undoes whatever it changes in `results/` (snapshot before and after, copy of `results/bazaar-live/`); the recorder files, the `bazaar:news` files (`news.jsonl`, news-summary.json) and `results/logs/` are left alone. Do not run it while another process is playing in dry-run: whatever that process writes during the check would also be undone.
- **`up.mjs`** — `pnpm bazaar:up`: runs the doctor (`--fast`, or `--skip-doctor`) and starts recorder (`pnpm bazaar:record`), viewer (`pnpm viewer`; if the port already serves the viewer it is reused, if another process holds it the next free one is used), play (`pnpm bazaar:play` in a loop, **dry-run by default**; `--play-args` adds flags), shadow broker (`pnpm bazaar:broker --shadow --poll-ms 5000`, in a loop; `--shadow` = `--dry-run --no-announce`, **always**, also with `--live`: it observes the bench for the Market Test; it is not started without .env.broker or with `--no-broker`), news (`pnpm bazaar:news --no-file-log`: Radio Rastro news for the viewer, display only) and audit (`pnpm bazaar:audit --watch`, read-only inefficiency monitor, the same in dry-run and live: writes audit.jsonl and audit-status.json in `results/bazaar-live/<date>/`; `--no-audit` does not start it; see [`src/audit/`](../../src/audit/AGENTS.md)). Output is prefixed and colored, and each child logs to `results/logs/<date>/<name>.log` (up events in `up-events.log`). Each child runs in its own process group: Ctrl-C (or SIGTERM) stops them all (SIGINT, SIGTERM after 5 s, SIGKILL after 10 s). A child that dies is restarted with growing backoff (2 s, 4 s… up to 60 s), at most `MAX_RESTARTS` (5) in 10 min; after that it stays "failed". Heartbeat every 10 s in `results/logs/up-status.json` (pid, start, mode, viewer, restarts, last tick seen, clock). In dry-run, play only runs with the gates open and the clock running (it polls `/api/clock` every 30 s; `--no-gate` runs it anyway). Live only with `--live --confirm`, printing LIVE in the terminal. `--detach`: relaunches it with nohup (output in up.log).
- **`down.mjs`** — `pnpm bazaar:down`: reads the pid from the heartbeat (results/logs/up-status.json), checks that it is `up.mjs` and sends it SIGTERM; if it has not stopped within 20 s, SIGKILL to the children's groups and to up.
- **`lib.mjs`** — `loadEnv`, `apiGet`, `portInUse`, `probeViewer` (free, viewer or other), `clockLine`, `alive`, `localDate`, `STATUS_FILE`.
