# src/dealers/ — Dealers

Negotiating with the dealers (Abuela, El Chato) through their API: plan of what to buy or sell, negotiator, message templates, patience, spend caps and the continuous `--serious` mode. Entry point: `main.ts` (`pnpm bazaar`).

## Files

- **`agent.ts`** — `BazaarAgent.step`: one step per tick (one thread per dealer, one message per thread and tick, one acceptance per tick). Handles persona_quota (until the next hour), cooloff (until_tick), sold_out and walked (target out for an hour). Run caps (`maxDeals`, `maxThreads`, `maxSpendTotal`): `done` stops the loop on reaching the deals or exhausting the conversations; `plan` prints the dry-run plan. With `team` (`TeamBudget`) it shares spend, cash floor (`--cash-floor`) and the acceptance per tick with the other dealers; `dealsPerHour` (menu quota, per game hour) blocks with `dealer-quota`. In rarity+set purchases, `revealedCards` reads the card she offers (`give.types` = "card:SAL-05" or `give.assets`) and the limit becomes our value of ONE more copy of that card (`nextCopyValue`; the limit never goes up): if we already have it (thread 493: RET-06 valued at 40, we paid 24 for a duplicate worth ~10) and her price exceeds the new limit, it is closed with the rule `named-card-revalue`; the line `named-card-revalue: she offers … → limit N (was M)` appears in the log and in the coordinator notes. **Purchase value of a card we already have**: the client's value cache is seeded with the `your_value` of our copies (what we lose if one leaves), so `valueOf` corrects it with the catalogue's copy marginals (`[1, 0.25, 0.1]`): next copy = value of the last ÷ marginal(n) × marginal(n+1); used by the planner, the resumption and the revaluation. **welcome_first_deal**: in the team's first conversation with a dealer (not Abuela or El Chato, `WELCOME_FIRST_DEAL_PAST`; and no other thread of ours with them in `/api/me/threads`) the view carries *welcomeFirstDeal* and the negotiator sends a counteroffer 1 P better (`welcome-counter`) and then accepts their price if it creates value (`welcome-first-deal`), so the deal counts as negotiated; the trace records *measuredLimit* and, if we accepted without having offered, *tookOpening* (took_opening: does not count as negotiated for the share) and the lesson *measured_limit* (their limit for that dealer and that band). Every finished conversation yields a `ThreadSummary` (in the trace, printed and passed to `onThreadSummary`).
- **Unlock chase** (`unlockChase`, `agent.ts`) — if the coordinator says a deal with this dealer would soon unlock a persona (e.g. Doña Pilar via El Chato) and no target has margin, the agent opens the least harmful deal from `chaseCandidates` (`planning/plan.ts`) with tolerance `UNLOCK_CHASE_TOLERANCE` = 2 P: buying at no more than value + 2 or selling a duplicate for at least value − 2. The line `unlock-chase pilar via chato: …` appears in the log and the intent carries the rule `unlock-chase` (later `unlock-chase/<rule>`). One thread at a time (the agent already has only one); if she appears in `me.unlocked`, the tolerance is withdrawn and the thread goes back to requiring positive value. Guardrails, menu guard, locks and cash floor unchanged.
- **One card, one buyer**: `TeamBudget.claimBuy`/`buyingElsewhere` record the card each dealer is buying, and another dealer does not ask for it at the same time (threads 407+408: RET-07 twice). **Packs and rarity+set only with `blindBuys`** (off by default).
- **Pack buying** (`packValueOf`, `agent.ts`) — with the estimated value of each pack type (the coordinator passes it from `GameState.packs`), the planner proposes `{buy: {pack}}` and the agent negotiates it like any purchase (negotiator's figure, template with `textMatchesPrice`, `checkStructure` requires exactly one pack of that type, budget and cash floor). Respects `per_team_per_hour` per pack type (game hours of each deal). If the dealer rejects the topic with 400/422, `pack-topic-unsupported` is recorded and no more packs are proposed to them in the run. Without `packValueOf` (`pnpm bazaar` mode) nothing changes.
- **`probe` / `onProbe`** (`agent.ts`) — the coordinator can give an egg phrase X for the thread's next counteroffer (it goes in the same message, with the decided figure); after sending it live it is recorded in `eggsTried`.
- **`DealerIntent` / `gate`** (`agent.ts`) — with `gate`, every POST of the agent (open, accept, counteroffer, hold, close) goes through the coordinator first; if it returns false nothing is sent and the thread state does not change. Without `gate`, the agent acts alone, as always.
- **`team.ts`** — `TeamBudget`: spend per hour and total on purchases, cash floor (270 P of the market + reserve) and one acceptance per tick for the whole team. The page reserve (SAL-09) only holds back purchases that bring a missing page card; loose-surplus purchases and packs do not touch it.
- **`dealer-profile.ts`** — `negotiatorForDealer` from the public traits: patience ⌊1 + 6 × patience⌉ messages (Abuela 6, El Chato 3) only up to level 2 (`PATIENCE_FROM_TRAIT_MAX_LEVEL`); at levels 3–5 the trait is prompt-only (withdrawal is decided by walk_after_rounds ± jitter), so `patienceBudgetFor` leaves it unknown, the negotiator uses the default one and it is measured with `PatienceLog`; impatient or strict dealer: moderate anchor (0.85 / 1.5× / 1.15×) and a single hold. Per-dealer overrides in `DEALER_OVERRIDES` (e.g. El Chato: patience 8, maximum step 1 P, no holds, sell anchor ~22 for uncommons). `dealsPerHourOf` (menu quota), `unlockedDealerIds` (`me.unlocked`), `gameHours` (t_hours of the clock).
- **`serious.ts`** / **`serious-run.ts`** — continuous mode: `clockGate` (pause or closed `doors`: wait until next_opens), `classifyError` (transient with `Backoff` 2 s → 60 s; handled by the agent; unknown ones stop), `statusLine` (one line per tick) and `runSerious` (one `BazaarAgent` per unlocked dealer with `requireMenu`: without a menu it opens nothing; dealers and menus re-read every 10 ticks; **menu guard**: `menuBlocks` of `planning/plan.ts` only sells what their `menu.buys` buys and only buys what their `menu.sells` sells; every purchase counts in the budget at its real price (on accept, accepted offer, cash drop or, failing that, the limit); respects max_open_threads_per_team of the clock; lessons only live).
- **`main.ts`** — CLI of `pnpm bazaar`.

## Usage

```bash
pnpm bazaar --dry-run --once --max-deals 2 --max-spend 50 --max-threads 2   # readable plan; no POST
pnpm bazaar --max-deals 2 --max-spend 50 --max-threads 2                     # live (with approval), stops after 2 deals
pnpm bazaar --dry-run --once --only "buy:uncommon:SAL,buy:common:SAL" --safety 1.0 --max-deals 2 --max-spend 40 --max-threads 2   # only those purchases, limit = value
pnpm bazaar --serious --dry-run --once   # serious mode, read-only: plans of each unlocked dealer and a status line
pnpm bazaar --serious                    # serious mode live (with approval): continuous, every deal that creates value
```

Flags: `--dry-run`, `--once`, `--max-spend` (P on purchases, cap of the run and of each hour; 120 by default), `--max-deals` and `--max-threads` (no cap by default), `--dealer` (abuela by default), `--only` (targets and order), `--safety` (fraction of the value used as limit; 0.9 by default, 1.0 = limit equal to value), `--buy-anchor-frac` (0.75), `--sell-anchor-mult` (2.0), `--sell-floor-anchor-mult` (1.3), `--patience-budget` (6), `--max-step` (3), `--step-mode` (adaptive | boulware), `--max-holds` (1), `--first-step-frac` (0: off). Serious mode: `--serious` (all unlocked dealers, no `--only`, safety 1.0, `--max-spend-hour` 60 and `--max-spend` 150 by default), minimum cash 270 + `--cash-reserve` (10) by default; with `--cash-floor N` the floor is N (plus `--cash-reserve` only if passed), and the status line warns if the floor exceeds the cash, `--lessons` (docs/bazaar/lessons.json).
